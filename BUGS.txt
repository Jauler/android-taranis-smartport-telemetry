Known bugs
==========


1. The terrain pack is opened on the UI thread
----------------------------------------------

Area: Settings > Terrain > Terrain data, terrain readouts
Files: ui/PrefsFragment.kt, manager/TerrainMonitor.kt, terrain/TerrainPack.kt

What happens:
  Opening a terrain pack reads its header and the complete tile index of
  every layer, and this happens on the UI thread:
  - PrefsFragment.updateTerrainInfo() opens the pack with TerrainLoader.open()
    only to show its description in the summary, and closes it again. It
    runs when the settings are created, on every onResume() and after each
    install or removal.
  - TerrainMonitor opens it when the data service starts, and again in
    reloadIfChanged() when the map screen comes back from the settings with
    another pack installed.

Effect:
  Small for the pack of Lithuania (145 x 111 tiles, about 64 KB of index for
  three layers), but it is disk I/O on the UI thread, and the cost grows with
  the pack: the format allows up to 16M tiles per layer (64 MB of index).
  On slow or broken external storage (the /sdcard FUSE problems seen on the
  tablet) the read can block and freeze the screen.

Suggested fix:
  Read only the header for the description (a TerrainPack.readDescription()
  that does not load the layer indexes), and open the pack for the monitor on
  its worker thread, publishing it to the UI thread when it is ready.
